# 1.LLM实现记忆功能思路与常见记忆模式

LLM实现记忆功能思路:
模型本身不会记忆任何上下文,只能依靠用户本身的输入去产生输出.
为LLM添加记忆功能非常简单,就是在Prompt中预留chat_history占位符,
将Human/AI的历史对话消息插入到占位符中,并实时保存他们的对话信息,
在每次对话时插入到占位符即可完整最简单的记忆功能.

ChatModel记忆功能:
将多次Human/AI历史对话组成消息列表,添加至每次提问请求的消息列表中.
LLM记忆功能
将多次Human/AI历史对话组成文本,添加至chat_history占位符中,组成新的提问文本.

Memory组件 常见记忆模式:
a.缓冲记忆: 最基础的记忆模式,将Human/AI生成消息全部存储起来,需要时将所有历史消息列表
传递到Prompt中,则LLM可以理解之前对话的内容,此方式在上下文窗口限制内是无损的.
优点:无损,完全保存.实现简单,兼容性好,所有LLM都支持
缺点:Token过长,响应变慢,成本增加,达到LLM令牌上限时过长的内容无法被记住.
对于上下文长度较小的模型,能记忆的内容极短.

b.缓冲窗口记忆:只保存最近几次的Human/AI历史消息,基于缓冲记忆思想,添加一个窗口K值,
只保存一定数量的历史信息,缺失之前的互动历史.
优点:有效限制TOKEN数量,对小模型友好,如不提问较远的关联内容,效果最好
实现简单,性能优异,所有大型模型都支持
缺点:不适合历史遥远的互动,会遗忘之前的历史.
如果对话内容长度较大,容易超过大模型的上下文限制

c.令牌缓冲记忆:只保存最近几次的Human/AI历史消息,基于缓冲记忆思想,添加一个令牌数max_tokens,
当聊天历史超过令牌数时,会遗忘之前的历史.
优点:可以基于大模型的上下文长度限制分配记忆长度
对小模型友好,,如不提问较远的关联内容,效果最好
实现简单,性能优异,所有大型模型都支持
缺点:不适合历史遥远的互动,会遗忘之前的历史.

d.摘要总结记忆:将历史消息进行总结,不传递完整消息而只传递总结的消息.对长对话内容最有用,
可以避免过度使用token.
优点:无论长期还是短息的历史都可以记忆.减少token数量,能记忆更多轮的对话历史.
对长对话效果明显,虽然初始使用token较多,使用摘要后token增长速度减慢.
对比常规缓冲内存相比,优势明显
缺点:记忆细节部分会丢失,如果内容较短反而增加token使用量.
历史记忆完全依赖摘要生成LLM的能力,要为摘要生成LLM分配token,
增加成本且未限制对话长度.

e.摘要缓冲混合记忆:结合摘要总结记忆与缓冲窗口记忆,对对话进行摘要总结,同时保留最近期互动中的原始内容,
不是简单的清除旧的历史,而是将他们编译成摘要与近期原始内容同时使用,
使用标记长度而不是交互数量来确定合适清除远期历史交互.
优点:长期短期记忆都可保存,长期为模糊记忆,短期为精准记忆.
减少token数量,能记忆更多轮的对话信息
缺点:长远历史互动为模糊记忆,总结摘要部分完全依赖摘要生成LLM的能力,
要为摘要生成LLM分配token,增加成本且未限制对话长度.

f.向量存储库记忆: 将记忆存储于向量存储中,并在每次调用时查询前K个最匹配的文档,能记忆所有内容,
细节部分比摘要总结要强,但是比缓冲记忆弱,token消耗方面比较平衡.
实现思想类似于RAG(增强检索)
优点:比摘要总结更强的细节,比缓冲记忆能存储更多内容,甚至无限长度.
消耗Token相对平衡.
缺点:性能相比其他模式要差,需要额外的Embedding模型与向量库支持
记忆效果受检索功能影响,好的非常好,差的非常差.

# 4.LangChain_ChatMessageHistory组件

BaseChatMessageHistory:
将记忆功能集成至LLM应用中需要解决两个核心问题:存储的历史信息是什么?如何检索历史信息?
由此可知,一个记忆类是由 历史消息存储 与 记忆的处理逻辑 两部分组成.
BaseChatMessageHistory 为langChain管理历史信息的基类,其中涵盖多种对历史消息的管理:
添加消息 清空历史消息 查看历史消息列表 查看历史消息文本 等.
所有扩展的历史消息组件均集成自该类.

InMemoryChatMessageHistory子类:
langchain_core包内置的对话消息历史类,将对话消息存储到临时的内存中.
其他第三方集成的聊天消息历史组件均通过langchain_community包导入.
https://github.com/langchain-ai/langchain/tree/langchain%3D%3D0.3.26/docs/docs/integrations/memory

# 5.langchain_Memory组件运行流程
Memory组件:
BaseMemory:
Memory组件的基类,非Runnable,封装大量基础方法.衍生出了两个子类SimpleMemory和BaseChatMemory.
BaseMemory 是一个功能完整的“记忆管理器”,而 BaseChatMessageHistory 是一个专一的“消息存储器”
BaseMemory 是策略，BaseChatMessageHistory 是存储.
BaseMemory 内部通常包含一个chat_memory属性,而这个属性正是一个BaseChatMessageHistory的实例！
BaseMemory 是一个更高级的抽象。它负责在链（Chain）的运行过程中，自动地、有策略地管理记忆

SimpleMemory:
实现了记忆组件的相关方法,但是不存储任何记忆,可以在不修改代码结构的情况下替换记忆组件,实现无记忆功能.
BaseChatMemory:
LangChain中内置的其他记忆组件的基类，针对对话历史进行了特定的封装，以适用聊天模型对话的场合.

BaseChatMemory运行流程及源码:
在LangChain的BaseChatMemory组件中,不同的属性与方法有不同的作用:
1.chat_memory(BaseChatMessageHistory):用于管理记忆中的历史消息对话.
2.output_key:定义AI内容输出键.
3.input_key:定义Human内容输入键.
4.return_messages:load_memory_variables函数是否返回消息列表，默认为False代表返回字符串.
5.save_context:存储上下文到记忆组件chat_memory中(存储消息对话).
6.load_memory_variables:生成加载到链的记忆字典信息(key:prompt中的变量,value:传入的值).
7.clear:清除记忆中的对话消息历史

# 6.langchain_缓冲记忆组件的使用与解析
缓冲记忆组件是 LangChain 中最简单的记忆组件，绝大部分都不对数据结构和提取算法做任何处理，就
是简单的原进原出，也是使用频率最高的记忆组件

缓冲记忆组件的类型:
ConversationBufferMemory:缓冲记忆,最简单,最数据结构和提取算法不做任何处理,将所有对
话信息全部存储作为记忆.可以返回消息列表或字符串.
ConversationBufferWindowMemory:缓冲窗口记忆,通过设定 k 值,只保留一定数量（2*k）的对
话信息作为历史.
ConversationTokenBufferMemory:令牌缓冲记忆,通过设置最大标记数量（max_token_limits）
来决定何时清除交互信息,当对话信息超过 max_token_limits时,抛弃旧对话信息.
ConversationStringBufferMemory:字符串缓冲记忆（早期 LangChain 封装的记忆组件）,等同
于 缓冲记忆,固定返回字符串,基本已不再使用.

# 7.langchain_摘要记忆组件的使用与解析
在 LangChain 中 摘要记忆组件 保留关键信息（重点记忆），移除冗余噪音（流水式信息）.

摘要记忆组件的类型:
a.ConversationSummaryMemory:摘要总结记忆组件,将传递的历史对话记录总结成摘要进行保存
（底层使用 LLM 大语言模型进行总结）,使用时填充的记忆为摘要,并非对话数据.
这种策略融合了记忆质量和容量的考量,只保留最核心的语义信息,有效减少了冗余,同时质量更高.
b.ConversationSummaryBufferMemory:摘要缓冲混合记忆,在不超过 max_token_limit的限制
下,保存对话历史数据;对于超过的部分,进行信息的提取与总结(底层使用 LLM 大语言模型进行总
结),兼顾了精确的短期记忆与模糊的长期记忆.

摘要缓冲混合记忆示例与注意事项:
ConversationSummaryBufferMemory 会将汇总摘要的部分默认设置为 system 角色,创建系统角色
信息,而其他消息则正常显示,传递的消息列表就变成:
    [ system , system , human , ai , human , ai , human ]。
但是部分聊天模型是不支持传递多个角色为 System 的消息,并且在 langchain_community 中集成的
模型并没有对多个 System 进行集中合并封装（Chat Model 未更新同步）,如果直接使用可能会出现报
错.
而且绝大部分聊天模型在传递历史信息时，传递的信息必须是信息组，也就是 1 条 Human 消息 + 1 条
AI 消息这种格式，例如百度的文心大模型，链接：
https://cloud.baidu.com/doc/WENXINWORKSHOP/s/clntwmv7t


# 8.实体记忆组件的使用与解析(版本较老,仅做了解)
 实体记忆组件介绍:
 实体记忆指的是跟踪对话中提到的实体,在对话中记住关于特定实体的既定事实,它提取关于实体
的信息(使用LLM),并随着时间的推移建立对该实体的知识(使用LLM),一般使用实体记忆来存储和
查询对话中引用的各种信息,比如人物、地点、事件等.
在 LangChain 内部封装了一个实体记忆类 ConversationEntityMemory,这个类可以从对话历史中提
取实体并生成描述(简单来讲,就是提取关键词+对应的描述),不过 ConversationEntityMemory 预
设的 Prompt 过于笨重,而且极度消耗 Token,并且对大模型的要求极高,所以实用度并不高.

# 9.记忆组件的持久化与第三方集成
 记忆组件的持久化:
 在 LangChain 中记忆组件本身没有持久化功能,但是可以通过chat_memory来将对话信息历史持久化,
 通过额外的数据库来存储汇总信息、摘要等技巧，从而实现记忆的持久化.
 以 ConversationSummaryBufferMemory 为例,如果想要持久化,可以使用带有持久化功能的chat_memory,
 并且利用外部的文件或者数据库管理 moving_summary_buffer 字段数据,从而实现整个记忆组件的持久化.
 在 LangChain 中,集成接入的第三方对话消息历史有近 50+ 个,涵盖了:
     Postgres、Redis、Kafka、MongoDB、SQLite 等,
 并且 ChatMessageHistory 可以完美接入到 Runnable 可运行协议的链条.
